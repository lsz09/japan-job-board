# 일본 취업 마감보드

마이나비, 리쿠나비, 원커리어, 외자취활의 공식 채용 페이지에 바로 접속하고, 관심 공고를 일본 시간 기준 마감일순으로 보는 정적 사이트입니다.

## 사용하기

1. 브라우저에서 `index.html`을 열면 **매일 확인한 공고**가 표시됩니다. 공고 유형, 업계, 지역, 참가 형식, 기업 규모, 마감 기간, 기업, 출처를 조합할 수 있습니다. 한 기업의 공고는 기본적으로 같은 카드에 나오며, **마감일별 보기**로 바꿀 수 있습니다. 보드는 일치하는 등록 공고를 모두 표시합니다. 배포 주소에서는 선택한 조건이 URL에 반영됩니다.
2. 회사명 아래에서 종업원 수, 업계, 본사 주소, 주요 사업을 볼 수 있습니다. 종업원 수와 **회사 자료**는 각각 근거 페이지로 연결됩니다.
3. 각 공고 아래에서 지원·참가 대상과 채용 직무, 체험 또는 설명회 내용을 확인합니다. 신청 전에는 **원문 보기**에서 자격과 마감일을 확인합니다.
4. 전체 목록에서 마감이 지난 공고를 보려면 **마감된 공고 포함**을 켭니다. 마감 시간이 공개되지 않은 일정은 표시된 날짜가 끝날 때까지 목록에 나옵니다.
5. **목록 확인 기록**에서 사이트별로 어느 목록을 열었는지, 다음에 어디부터 확인할지, 상세 확인을 기다리는 공고가 몇 건인지 볼 수 있습니다.
6. 지원을 마친 공고에서 **지원한 공고** 버튼을 누르면 **지원한 공고** 탭에 저장됩니다. 마감이 지나거나 전체 목록에서 사라져도 저장한 기록을 열 수 있습니다. **캘린더**에서는 저장한 공고의 마감일을 일본 시간으로 표시합니다. 마감일이 미정인 공고는 지원 목록에 남습니다.
7. 지원 기록은 현재 브라우저에서 마감보드를 연 주소에 저장됩니다. 로컬 파일과 배포 주소, 또는 다른 브라우저나 기기 사이에는 기록이 공유되지 않습니다. **지원 기록 삭제**를 누르면 지원 목록과 캘린더에서 함께 사라집니다.

매일 확인한 공고는 `daily-data.js`에서 불러옵니다. 예약 작업으로 이 파일을 갱신한 뒤 브라우저를 새로고침하면 새 목록을 볼 수 있습니다. 로컬 파일을 갱신하는 예약 작업이 실행되려면 PC가 켜져 있고 ChatGPT 데스크톱 앱이 실행 중이어야 합니다. [OpenAI 예약 작업 안내](https://learn.chatgpt.com/docs/automations?surface=app)

## 매일 공고를 선별하는 기준

- 매일 네 사이트에서 `coverage`에 등록된 공개 목록부터 순회합니다. 미완료 목록은 `nextUrl`이나 `note`의 위치에서 이어가고, 최신 공고가 앞쪽에 추가됐는지 첫 페이지도 다시 봅니다. 이전 순회를 완료한 목록은 새 순회를 첫 페이지부터 시작합니다.
- 마이나비는 IT 계열 직무 체험과 직종 연구 목록을 우선 확인합니다. 원커리어는 28졸·IT 세부 직종·300명 이상 인턴십 검색과 28졸 엔지니어 키워드 설명회·선고 검색을 사용합니다. 외자취활은 2028졸에 IT 엔지니어와 시스템 엔지니어를 함께 선택한 목록을 사용합니다. 각 공고의 실제 직무와 채용 법인 사원 수는 원문과 회사 자료에서 확인합니다.
- 공개 화면에 표시된 다음 페이지 링크나 더보기 버튼을 차례로 따라갑니다. 다음 페이지를 열면 결과가 실제로 달라졌는지 확인합니다. 주소가 같아도 새 결과가 표시된 묶음은 구분해서 기록합니다. 다음 페이지의 주소를 알 수 없으면 `note`에 다시 열 목록과 사용할 버튼 또는 페이지 번호를 기록합니다.
- 목록에서 조건에 해당할 수 있는 개별 공고 링크를 모두 기록합니다. 목록 제목만으로 졸업연도, 직무, 사원 수를 판단할 수 없으면 상세 확인 대상으로 남깁니다. 그 페이지를 벗어나기 전에 아직 확인하지 못한 링크를 `pending`에 저장합니다. 대기 링크는 확인을 마치거나 조건 불충족이 확인될 때까지 유지하고, 여러 목록에서 나온 동일 원문은 한 번만 확인합니다.
- 페이지가 열리지 않거나 결과가 표시되지 않으면 해당 위치와 이유를 남깁니다. 공개 브라우저 화면이나 사이트의 공개 필터로 같은 범위를 다시 시도할 수 있습니다. 시간 제한으로 중단하면 해당 위치와 대기 목록을 남겨 다음 실행이 이어가도록 합니다.
- 목록 순회 후 각 사이트에서 검색어를 바꿔 누락을 보완합니다. 업계 필터가 걸린 목록도 있으므로 제조·금융 등 다른 업계의 소프트웨어, 시스템·인프라, 클라우드·보안, 데이터·AI 엔지니어 공고를 확인합니다. 네 유형과 온라인·간토 외 지역도 검색합니다. 보완 검색은 목록 페이지 수에 넣지 않습니다.
- 28졸(2028년 졸업 또는 2028년 4월 입사 대상), IT 엔지니어 관련 공고를 모든 업계에서 찾습니다. 채용 법인 자체의 사원 수가 300명 이상인 경우를 포함합니다.
- 인턴십·직무 체험, 회사설명회, 조기선고, 본선고는 신청 대상의 실제 유형으로 분류합니다. 설명회 참석 후 조기선고 기회가 주어지는 경우는 회사설명회입니다.
- 선고는 공고의 근무지, 인턴십과 설명회는 공고의 개최지를 씁니다. 본사 주소로 대신하지 않습니다. 장소가 없으면 지역 미정, 온라인 진행이면 온라인으로 표시합니다.
- 각 공고에는 상세 페이지 링크와 사원 수 확인 링크를 남깁니다. 원문에서 수시 모집 또는 현재 접수 중임을 확인했지만 마감일이 없으면 `date`와 `time`을 비워서 추가합니다. 날짜가 비어 있다는 이유만으로 진행 중인 공고를 빼지 않습니다. 수시 모집은 매일 다시 열어 모집 종료 여부를 확인합니다.
- 새 공고를 추가하거나 갱신할 때 원문에서 지원·참가 대상과 실제 직무·행사 내용을 확인해 각각 한국어로 요약합니다. 필수 자격, 우대 조건, 권장 대상을 구분하고 원문에 없는 조건을 추정하지 않습니다. 기업 소개는 해당 법인의 공식 자료에서 확인합니다.

`daily-data.js`에는 `window.dailyScan` 객체를 둡니다. `checkedAt`은 최근 검색 시각(ISO 8601), `sources`는 출처 코드별 `checked`(등록 목록의 순회와 상세 확인 완료), `partial`(일부 확인), `unavailable`(확인 어려움)입니다. 기존 공고를 갱신할 때 기업 소개와 공고 요약도 보존합니다.

- `coverage`는 출처 코드별 목록 배열입니다. 각 목록에는 고정된 `id`, `label`, `startUrl`, `status`, 마지막 시도 날짜 `checkedOn`(JST), 실제 모집 결과를 열어 본 `pages` 배열(`{ "url": "…", "label": "…" }`), 상세 확인이 남은 `pending` URL 배열, `nextUrl`(확인한 이어보기 링크가 있으면 기록), `note`(중단 이유나 화면에서 이어갈 방법)를 둡니다. 같은 목록 페이지를 재확인해도 중복으로 세지 않습니다.
- 목록 상태는 `pending`, `in_progress`, `partial`, `unavailable`, `complete`입니다. 모집 결과의 마지막 페이지까지 확인하고 상세 확인 대기가 모두 끝난 목록만 `complete`로 기록합니다. 완료 범위는 해당 공개 목록의 필터에 한정됩니다. 결과가 로딩되지 않았거나 다음 페이지를 확인할 수 없으면 완료로 표시하지 않습니다. 진행 기록과 확인을 마친 공고를 함께 저장하며, 기존에 확인한 공고를 이번 목록에서 못 찾았다는 이유로 삭제하지 않습니다.
- `jobs`의 공고 항목에는 `id`, `company`, `title`, `type`, `source`, `date`, `time`, `url`, `employeeCount`(숫자), `companySizeUrl`(근거 링크), `regions`(지역 코드 배열), `location`(선택, 지역명), `verifiedOn`(공고 확인 JST 날짜), `audience`(지원·참가 대상), `summary`(직무·체험·설명회 내용)를 기록합니다.
- `companies`에는 공고의 `company`와 같은 이름을 키로 사용합니다. 각 기업에는 `industry`, `address`(회사 자료에 나온 본사 주소), `business`(한국어 주요 사업 요약), `url`(회사 자료 링크)을 기록합니다. 사원 수가 근사치로 공시되면 `sizeApproximate: true`를 함께 기록합니다.
- 유형은 `internship`, `briefing`, `early`, `main`을 사용합니다. 출처는 `mynavi`, `rikunabi`, `onecareer`, `gaishi`입니다. 날짜와 시간은 각각 `YYYY-MM-DD`와 `HH:mm`으로 입력합니다.
- 지역은 `hokkaido`, `tohoku`, `kanto`, `chubu`, `kinki`, `chugoku`, `shikoku`, `kyushu`, `nationwide`, `online`, `unknown`을 사용합니다. 온라인과 대면을 모두 선택할 수 있으면 `regions`에 `online`과 해당 지역을 함께 기록합니다.
- 업계는 `it`, `manufacturing`, `finance`, `consulting`, `real-estate`, `retail`, `infrastructure`, `media`, `healthcare`, `other`를 사용합니다.

## GitHub Pages에 올리기

1. 이 프로젝트의 파일을 GitHub 저장소의 `main` 브랜치 최상위에 올립니다.
2. 저장소의 **Settings → Pages**에서 **Deploy from a branch**를 선택합니다. 브랜치는 `main`, 폴더는 `/(root)`로 설정하고 저장합니다.
3. 배포가 완료되면 Pages 설정에 표시된 주소를 엽니다. 로컬에서 갱신한 공고는 `daily-data.js` 변경을 게시 브랜치에 반영하면 이 주소에도 표시됩니다. [GitHub Pages 배포 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
